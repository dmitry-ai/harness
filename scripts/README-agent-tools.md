# Назначение

Общий код находится в `.agents/scripts/agent_tools/`.
Файлы `.agents/scripts/*.py` из этого набора — короткие точки входа в него.
Импорт модулей не запускает браузер, запись журнала, сборку контекста или коммит.
Правила описывают, когда запускать команду; сама среда не исполняет Python из Markdown.
Git-хуки не устанавливаются.

# Установка

Нужен Python 3.10 или новее.
Из корня проекта выполните:

```text
python -m pip install -r .agents/scripts/requirements-agent-tools.txt
python -m unittest discover -s .agents/tests -p test_agent_tools.py -v
```

Markdown-парсер нужен для проверки ссылок и Markdown-файлов перед коммитом.
Журнал, резервные копии, проверка наличия Statements и сборка контекста используют стандартную библиотеку.
Зависимости устанавливайте в окружение проекта.
Новое окружение тоже можно держать внутри `.agents`: создайте его командой `python -m venv .agents/.venv` и активируйте перед установкой зависимостей.
Папка окружения и кэши Python исключены из Git через `.agents/.gitignore`.

# Журнал

```text
python .agents/scripts/record_step.py --dir ".agents/data/journal" --req "Точный запрос" --res "Точный окончательный ответ"
python .agents/scripts/record_step.py --dir ".agents/data/journal" --req-file "request.txt" --res-file "response.txt"
python .agents/scripts/validate_step.py --dir ".agents/data/journal" --step 1
python .agents/scripts/validate_step.py --dir ".agents/data/journal" --all
```

Указывайте каталог, выбранный пользователем для текущего чата.
Файлы на входе нужны только если они уже существуют или многострочный текст нельзя безопасно передать строкой.
Скрипт сохраняет UTF-8 без изменения переносов строк и проверяет записанные байты.
Номер выбирается по обеим папкам и незавершённым резервированиям в `.agents/data/.journal`.
`--step N` допускает только свободный положительный номер.
Перезаписи существующего шага нет.

Параллельные процессы согласуют запись через блокировку ОС в `.agents/data/.journal/writer.lock`.
Во время записи в `.agents/data/.journal/N.json` временно сохраняются токен, точные тексты, хеши и статус `pending`.
После успешной записи и проверки `req/N.md` и `res/N.md` файл резервирования `N.json` удаляется, чтобы не накапливать копии завершённых шагов.
В пользовательском каталоге журнала создаются только папки `req/` и `res/`.
Файл блокировки остаётся в `.agents/data/.journal/writer.lock`, но сама блокировка освобождается ОС при завершении процесса.

Две отдельные записи файлов не являются одной атомарной операцией файловой системы.
При аварии резервирование остаётся в `.agents/data/.journal/N.json` со статусом `pending`, валидатор сообщает незавершённость, а новый писатель использует следующий номер.
Для восстановления именно этого резервирования:

```text
python .agents/scripts/record_step.py --dir ".agents/data/journal" --recover 1 --token "TOKEN_FROM_RECEIPT"
```

Восстановление дописывает отсутствующие файлы только при совпадении токена и уже существующих байтов, после чего удаляет `N.json`.
Конфликтный или частично записанный файл сохраняется для разбора; автоматически перезаписывать его нельзя.
Валидатор не анализирует разрешение на работу по словам запроса и не сканирует соседние черновики.
Для дополнительной структурной проверки можно явно передать `--file PATH` один или несколько раз.

# Резервная копия

```text
python .agents/scripts/snapshot_draft.py "Letters/my/result/EN/draft.md" --turn chat-20261011-2
```

Запускайте до первой правки существующего черновика в ходе.
Используйте уникальный ID чата и хода.
Сохраняются реальные байты в соседний `draft.prev.md` и в `.agents/data/.draft-snapshots/<turn>/draft.md` с хешем.
Повтор с тем же ID проверяет исходную копию и не заменяет её промежуточной редакцией.
Новый ход получает новый ID.
Обнаруженные после снимка пользовательские правки требуют отдельного сохранения новой исходной версии.
Скрипт не блокирует редактор пользователя и не заменяет проверку актуальности файла непосредственно перед правкой.

# Ссылки

```text
python .agents/scripts/validate_links.py "report.md"
python .agents/scripts/validate_links.py "report.md" --local-anchors --unique-urls
python .agents/scripts/validate_links.py "report.md" --network
python .agents/scripts/validate_anchors.py "report.md" --timeout 15
```

Все целевые файлы задаются явно.
Отсутствие аргумента или подходящих URL для сетевой проверки — ошибка, а не успешная пустая проверка.
Обычная проверка использует Markdown-парсер и HTML-парсер.
Она выявляет некорректные HTTP-адреса и повторные явные HTML-якоря.
`--local-anchors` проверяет ссылки на явные `id`/`name` в этом файле.
Автоматические якоря заголовков зависят от конкретного Markdown-рендерера и требуют отдельной проверки.
`--unique-urls` включайте только для документа с требованием уникальности внешних источников.
`--include-code` дополнительно проверяет URL в строчных обратных кавычках.
Блоки программного кода не считаются ссылками документа.

Валидатор не запрещает Markdown, `www.`, `%`, query-параметры и завершающий слэш сами по себе.
Сокращение адреса и правила оформления конкретного письма проверяются с учётом его назначения.
Код не изменяет проверяемый текст.

Сетевые команды делают обычные HTTP-запросы без браузерной авторизации.
Сохраняются HTTP-статус и адрес после перенаправлений.
Наличие якоря подтверждается только в исходном HTML.
`not-found-in-source` означает отсутствие в этом HTML, а не доказанное отсутствие в DOM после JavaScript.
Проверка видимости, перехода, аккаунта и содержательной пригодности страницы остаётся за браузерным исследованием.
Код возврата `0` означает прохождение выбранных проверок, `1` — ошибку данных или команды, `2` — неподтверждённый сетевой результат.

# Контекст

Скопируйте `.agents/context.example.json` в `.agents/context.json` и укажите реальные источники проекта.
Пример намеренно не является активной конфигурацией нового проекта.
Порядок `sections` задаёт порядок разделов.
`files` перечисляет обязательные файлы, `globs` — маски, `exclude` — исключения, `letters` — корни переписки с авторами и приоритетом языков.
Для необязательного пустого раздела укажите `optional: true`.
Пути разрешаются относительно явно переданного корня проекта.
Выход за этот корень и перезапись источника выходным файлом запрещены.

```text
python .agents/scripts/generate_context.py --root "." --config ".agents/context.json" --dry-run
python .agents/scripts/generate_context.py --root "." --config ".agents/context.json"
```

Сначала изучите список источников в конфигурации и результат проверки без записи.
Источники включаются полностью, с указанием пути и автора письма.
Их заголовки и блоки кода не переписываются.
Для письма используется первый настроенный язык, затем `final.md`, при его отсутствии `draft.md`, затем `.md`.
Пустой существующий `final.md` вызывает ошибку.
Новые годы и вложенные номера писем не требуют изменения кода.
Каталоги авторов идут в порядке конфигурации, письма внутри — по пути.
Для иного порядка задайте источники явно через `files`.
При ошибке сборки существующий контекст не заменяется.

# Коммит

```text
python .agents/scripts/safe_commit.py --repo "." --file "report.md" --file "KB/topic.md" -m "Update analysis"
python .agents/scripts/safe_commit.py --repo "." --file "report.md" --file "KB/topic.md" -m "Update analysis" --execute
```

Сначала самостоятельно изучите diff и добавьте в индекс только порученные файлы.
Список индекса должен точно совпадать с `--file`.
Непроиндексированные правки выбранных файлов блокируют коммит.
Без `--execute` выполняется только проверка.
Команда не пересобирает контекст, не делает `git add` и не отправляет изменения на сервер.
Одновременную правку выбранных файлов другим процессом нужно исключить на время коммита.
Проверка не определяет по Git-статусу, кем написан код и разрешено ли его фиксировать.

# Statements

```text
python .agents/scripts/validate_statements.py "KB/Verification/Statements"
```

Проверяется наличие непустых UTF-8-файлов `.md` и `Test.md` в каждом числовом каталоге.
Наличие слова `curl`, Markdown-ссылки или фразы `Chrome CDP` не доказывает ошибку методики.
Достоверность теста проверяется по его действиям и фактическому результату.
