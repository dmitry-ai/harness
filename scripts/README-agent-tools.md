# Среда
Пользователь работает через `/upwork-init <URL>` в Antigravity 2.0 UI. Ниже — внутренние инструменты агента для детерминированных операций.
Python 3.12+; зависимости: `python -m pip install -r <scripts>/requirements-agent-tools.txt`.
Модели, часовой пояс и пути — в `../runtime.json`.
`python <scripts>/upwork_project.py doctor` проверяет постоянно активные правила и сообщает размер и параметры запуска.
`python <scripts>/upwork_project.py install-global` добавляет навык и worker в нативные глобальные манифесты, сохраняя остальные entries; глобальные правила анализа не устанавливает.

# Проект
`inspect URL --output ꘖ/data/<свой каталог>/source.json` один раз читает точно выбранную вкладку; `--tab-id` разрешает неоднозначность.
Вложения сохраняются рядом в `attachments`; имя/хост/размер ограничены, cookies фильтруются, перенаправления между хостами удаляют credentials.
Снимок содержит время, выбранную вкладку, фактически доступную историю, ошибки и `coverage`; полная история не предполагается.
`init URL --from-json source.json --domain <домен или тема> --date YYYY-MM-DD` не делает браузерных запросов.
`--site-hypothesis site.json` передаёт отдельно доказанную гипотезу идентификации по схеме ниже; без неё сайт не установлен.
Номер и соответствие job_id/каталога защищены общей блокировкой; повтор сохраняет путь и материалы.
В рабочем daily-каталоге init регистрирует штатный проект и папку Folders `Upwork / Proposals / YYYY / MM / DD` по дате его пути. Привязка — `projectFolderMap[project_id]` в `runtime.paths.folders_json`; отсутствующий/неверный файл вызывает ошибку. Результат содержит `folder_id`, `folder_path`, `folders_file`.
`register <проект> [--domain <имя>]` повторяет только регистрацию и назначение папки; сохраняет существующие ID, имя, настройки и разговоры, не меняет KB. Тестовый `--no-register` не предназначен для обычного `/upwork-init`.
`configure <проект>` только создаёт отсутствующие нативные манифесты/локальные настройки; существующие каталоги и конфигурации не преобразует.
Обновления KB после init выполняет агент по правилам; регенерации поверх дополненных документов нет.
Файлы свидетельств находятся в `ꘖ/KB/Evidence`; снимок неизменяем и адресуется SHA-256, вложения копируются с проверкой хеша.

# Анализ
`validate-analysis analysis.json [--render <новый Markdown>]` проверяет пять этапов, связи, оценки и наличие доказательств; истинность и пригодность ссылок проверяются отдельно.
Корневые списки: `identity`, `concerns`, `misconceptions`, `causes`, `methods`.
Пустой список требует пояснения `notes.<имя>`; отсутствие заблуждений допустимо.
Запись H: `id`, `essence`, `for`, `against`, `probability_percent` (целое 0–100), `assessment_basis`.
Запись M: вместо `probability_percent` — `score_percent` и `criterion`.
Каждый довод `for`/`against`: `argument`, `source`, дословная `quote`; для документации добавь `documentation: true`, URL обязан содержать anchor.
`causes[].addresses` ссылается на ID беспокойств; `methods[].addresses` — на причины или задачи; ID уникальны и устойчивы.
Неизвестность описывается как H с конкретными доводами и экспертной оценкой; отсутствие наблюдения не заменяется фиктивным F.

# Делегирование
В текущей беседе UI используй `invoke_subagent`: `self` для сложной работы A.A, `af-worker` для простой работы A.F. Вызовы и результаты должны быть видны в панели субагентов.
`self` наследует модель A.A; `model: flash` выбирает tier. Сопоставляй фактические метаданные с требуемыми версиями/High в runtime.json; без метаданных точная модель не проверена.
Анализ, архитектуру и независимую предметную рецензию поручай A.A; формальные проверки и извлечение — A.F. Внутренние Python-скрипты не запускают LLM-сеансы.

# Журнал
`record_step.py --dir <журнал> --req-file request.txt --res-file response.txt` сохраняет точные UTF-8-байты; `--step N` требует свободного номера.
`validate_step.py --dir <журнал> --all` проверяет пары и незавершённые резервирования.
Состояние: `ꘖ/data/.journal/<ID журнала>`; восстановление: `record_step.py --dir <тот же журнал> --recover N --token <токен>`.
Резервирование связано с каноническим каталогом и хешами; чужой конфликтный файл не перезаписывается.

# Снимки
`snapshot_draft.py <draft.md> --turn <ID хода>` сохраняет реальные байты в соседний draft.prev.md и архив `ꘖ/data/.draft-snapshots/<ход>/<ID файла>`.
Несколько черновиков одного хода независимы; повтор не заменяет исходный снимок промежуточной редакцией.

# Ссылки и контекст
`validate_links.py <файлы> --local-anchors` проверяет локальные файлы, явные/Markdown anchors и JSON pointers; `--unique-urls` — явная политика без повторов.
Автоматические Markdown anchors проверяются по GitHub-подобной схеме; для иных рендереров нужна предметная проверка.
`validate_anchors.py <файлы> --include-code` проверяет anchors в исходном HTML по HTTP; это не доказательство DOM, авторизации или смысла страницы.
Коды: 0 — выбранные проверки прошли; 1 — ошибка входа; 2 — сетевой результат не подтверждён.
`generate_context.py --root <проект> --config <проект>/.agents/context.json [--dry-run]` включает источники полностью, сохраняя текст и границы блоков.
Неполные пары журналов, пустой final и отсутствующий обязательный источник блокируют замену существующего контекста.
Пути ограничены корнем; выходной файл не может заменить источник.

# Git и реестр утверждений
`safe_commit.py --repo <корень> --file <путь> -m <сообщение> [--execute]` требует точного совпадения списка с индексом, проверяет unstaged/conflicts/Markdown и не выполняет add/push.
`validate_statements.py <каталог>` проверяет непустые `.md` и `Test.md` в числовых папках; наличие файлов не доказывает истинность тезиса.

# Проверка
`python -m unittest discover -s <.agents>/tests -p test_*.py -v`.
Для регрессии по сохранённым реальным данным задай `UPWORK_CAPTURE_DIR`: тест читает `*/source.json`, создаёт временные проекты и проверяет повторный init; браузер и исходные проекты не изменяет.
При очистке удаляй только собственные временные файлы; существенные доказательства и текущие резервирования сохраняй.
