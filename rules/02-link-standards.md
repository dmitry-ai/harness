# Раздел 2. Стандарты форматирования и проверки ссылок

17. **Авторитетность источников:** Ссылки на документацию должны вести на официальные сайты вендоров (Google, Meta, Apple, Mozilla, Microsoft, AWS, Stripe, Shopify, WooCommerce, Magento и др.). При отсутствии официальной документации допустимо использовать авторитетные профильные ресурсы.
18. **Точность до абзаца/фрагмента (Anchor links):** Ссылки на документацию должны быть точными вплоть до конкретного раздела или фрагмента (якоря), подтверждающего технический тезис. Исключения допустимы только при отсутствии на странице fragment identifier.
19. **Органичное встраивание ссылок:** Ссылки на документацию должны быть органично встроены непосредственно в текст пункта предложения, а не выноситься отдельным списком в конец.
20. **Принцип максимальной краткости ссылок (`as short as possible`):** Записывать ссылки в минимально возможной форме без избыточных сегментов.
21. **Удаление слагов статей:** В URL статей справочных центров (Zendesk, Freshdesk и др., например `/articles/<ID>-slug`) обязательно отсекать slug, оставляя только числовой ID статьи: `articles/<ID>` (пример: `https://help.example.com/hc/en-us/articles/12345678#anchor`).
22. **Удаление префикса `www.`:** Исключать префикс `www.` из ссылок, если сервер открывается без него (`https://example.com` вместо `https://www.example.com`).
23. **Удаление замыкающего слэша:** Исключать символ `/` на конце URL пути, если он не требуется веб-сервером строго (`https://example.com/path` вместо `https://example.com/path/`).
24. **Параметр языка для документации Google:** Для всей документации Google (Google Tag Manager, Google Analytics 4, Google Cloud, Firebase) обязательно добавлять параметр `hl=en` для фиксации английской локализации (пример: `https://support.google.com/tagmanager/answer/6102821?hl=en#anchor`).
25. **Категорический запрет UTM-меток:** Не включать в URL ссылок на документацию UTM-метки, токены кампаний и прочий трекинговый мусор (`utm_source`, `utm_medium` и т.д.).
26. **Отказ от Markdown-ссылок в коммерческом предложении:** Ссылки на документацию внутри коммерческого предложения оформлять обычным текстом БЕЗ Markdown-скобок (писать `https://example.com`, а не `[example](https://example.com)` или `[https://example.com](https://example.com)`).
27. **Бэктики для технических ссылок и эндпоинтов:** Ссылки на исполняемые скрипты, эндпоинты, файлы репозитория, дампы и внутренние страницы аналитики оборачивать в обратные кавычки (например, `https://data.example.com/...`, `https://github.com/...`).
28. **Отказ от бэктиков для клиентских статей:** Ссылки на справочные статьи вендоров для клиента указывать обычным текстом без обратных кавычек.
29. **Уникальность ссылок в предложении (0 Duplicate URLs):** В тексте предложения категорически запрещено дублировать одни и те же ссылки (0 duplicate URLs). Контролируется скриптом валидации.
30. **Ссылки на параграфы (§) при повторном упоминании:** При необходимости сослаться на источник, который уже упоминался ранее в предложении, ссылаться на номер параграфа (§), в котором он приведен.
31. **Обязательная проверка в браузере Chrome:** Все ссылки перед добавлением в предложение должны быть проверены в браузере Chrome пользователя через CDP (`--remote-debugging-port=9222`), а не через `curl`.
32. **Проверка статус-кода:** Целевой URL должен успешно открываться (HTTP 200). Запрещены ссылки, возвращающие "Page not found" (HTTP 404).
33. **Проверка скролла через `DOM Rect`:** При наличии якоря (#anchor) обязательно проверять в Chrome, что страница реально скроллится на нужный фрагмент, проверяя координаты через `DOM Rect` целевого элемента.
34. **Соответствие контента теме:** Текст на открытой странице обязан точно доказывать утверждение предложения.
35. **Режим проверки без инкогнито:** При проверке ссылок использовать рабочий профиль Chrome пользователя (не инкогнито), если не указано иное.
36. **Обязательное закрытие проверочных вкладок в Chrome:** Для проверки открывать ссылки в отдельных вкладках, которые обязательно закрывать сразу после завершения проверки (не оставлять за собой мусор в браузере пользователя).
37. **Проверка на защиту от ботов:** Страница не должна блокироваться Cloudflare, reCAPTCHA или аналогичными системами защиты.
