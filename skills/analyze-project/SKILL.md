# Первичный анализ нового проекта Upwork (`/analyze-project`)

При вызове `/analyze-project <url>` (или передаче ссылки `https://www.upwork.com/jobs/~...`) выполни следующий детерминированный процесс:

## Шаг 1. Неразрушающая выгрузка данных через CDP
1. Извлеки полные метаданные вакансии, историю 50 прошлых заказов клиента, описания открытых/публичных вакансий и вложения через детерминированный инструмент (не закрывая и не переключая вкладки пользователя на мониторах 1 и 2):
   ```powershell
   python "C:\work\upwork\code\AI\primary\result\.agents\scripts\upwork_project.py" inspect "<url>" --attachments-dir "$env:TEMP\upw_att"
   ```
2. Если у проекта есть графические или текстовые вложения (`saved_attachments`), обязательно изучи их через `view_file` (на скриншотах Google Ads / GTM / GA4 / CMS часто присутствуют точный домен клиента, ID контейнеров и тексты ошибок).

## Шаг 2. Определение домена клиента или темы проекта
1. Сопоставь кандидатов домена из описания текущей вакансии, описаний прошлых и параллельных публичных вакансий, отзывов фрилансеров и скриншотов вложений.
2. Если домен сайта клиента установлен с высокой достоверностью — используй его без `https://` и `www.` (например, `scoutandnimble.com`, `flexecharge.com`).
3. Если домен однозначно установить невозможно — сформируй краткое тематическое название (например, `Magento & Portugal`).

## Шаг 3. Детерминированная инициализация директории и базы знаний
1. Запусти инициализатор проекта:
   ```powershell
   python "C:\work\upwork\code\AI\primary\result\.agents\scripts\upwork_project.py" init "<url>" --domain "<domain_or_topic>" --site-note "<краткое обоснование домена>"
   ```
   Скрипт автоматически:
   - Создаёт директорию `C:\work\upwork\code\proposals\daily\YYYY\MM\DD\<N> - <domain_or_topic>`.
   - Создаёт корневой файл `.md` (`# <Название>\nhttps://upwork.com/jobs/~...`).
   - Заполняет `KB/Project.md` (`# 1. Клиент`, `# 2. Текущий проект клиента`, `# 3. Прошлые проекты клиента`).
   - Портирует начальные данные в `ꘖ/KB/` (`Client.md`, `Website.md`, `Projects.md`, `Glossary.md`, `.md`).
   - Подключает `.agents` к единому источнику `C:\work\upwork\code\AI\primary\result\.agents` и создаёт локальный файл проектных правил `.agents/rules/90-project.md` и `.agents/context.json`.
   - Создаёт `ꘖ/data/.journal/`, `ꘖ/data/.draft-snapshots/`, `ꙮ/1 - Анализ/{req,res}` и генерирует `ꙮ/0/Context.md`.
   - Регистрирует проект в плагине `Folders` Antigravity (`%USERPROFILE%\.gemini\config\projects\<uuid>.json` и `folders.json`).
2. После этого шага `KB/Project.md` больше не изменяется (`KB-1`); все дальнейшие уточнения и результаты исследования сайта вносятся только в `ꘖ/KB/`.

## Шаг 4. Делегирование подзадач `A.F` и подготовка глубокого анализа `A.A`
1. Главный агент `A.A` (`Gemini 4 Argon` High) может делегировать субагенту `A.F` (`af-worker`, `Gemini 3.8 Flash` High) проверку технических фактов о сайте клиента (DNS, HTTP-редиректы, заголовки, наличие тегов), а также поиск и верификацию точных `#anchor` в официальной документации.
2. Дополни модули `ꘖ/KB/Client.md`, `ꘖ/KB/Website.md`, `ꘖ/KB/Projects.md`, `ꘖ/KB/Glossary.md` проверенными техническими деталями.
3. Составь полный аналитический отчёт для `ꙮ/1 - Анализ/res/1.md`, включающий три обязательных блока:
   - **Раздел 1. Идентификация клиента и определение его сайта** (разбор всех гипотез домена).
   - **Раздел 2. Что беспокоит клиента в текущем проекте и какие источники беспокойств он намерен закрыть этим проектом (§26.1)**.
   - **Раздел 3. Какие заблуждения клиента видны в его описании проекта (§26.2)**.
4. Каждая гипотеза во всех трёх разделах обязана строго следовать структуре (§27, `DOC-8`):
   - **Суть** (включая ссылку)
   - **Доводы за** (с точными цитатами `«...»` и ссылками на `KB/Project.md#...`, `ꘖ/KB/...#...` и внешнюю документацию с точностью до `#anchor` согласно `LINK-2`)
   - **Доводы против**
   - **Экспертная оценка правдоподобности** (в `%`)
   - Без таблиц Markdown (`DOC-4`), каждое предложение на отдельной строке (`DOC-6`).

## Шаг 5. Запись журнала, валидация, пересборка `ꙮ/0/Context.md` и очистка `ꘖ/data/`
1. Запиши запрос и ответ в `ꙮ/1 - Анализ/` через `record_step.py`.
2. Проверь локальные и внешние ссылки и `#anchor` через `validate_links.py` и `validate_anchors.py`.
3. Пересобери `ꙮ/0/Context.md` через `generate_context.py --root "<project_dir>" --config "<project_dir>/.agents/context.json"`.
4. Удали все временные файлы в `ꘖ/data/` (включая временные скачанные вложения), оставив только `.journal/`, `.draft-snapshots/` и `context.lock`.
