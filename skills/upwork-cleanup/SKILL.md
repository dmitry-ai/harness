# Очистка пустых проектов Upwork

Обычный `/upwork-cleanup` означает выполнить очистку в обеих системах, независимо от среды запуска.
В Codex также доступен `$upwork-cleanup`.
Если пользователь просит только предварительный просмотр, выполни только проверку без `--apply`.

Общий инструмент: `C:/work/upwork/code/AI/primary/result/.agents/scripts/upwork_project.py`.
Определи текущую среду из беседы и передай `--platform codex` или `--platform antigravity`.

1. Выполни `cleanup --platform <среда>` и прочитай JSON.
2. При обычном запуске выполни `cleanup --apply --platform <среда>` для допустимых проектов; дополнительное подтверждение не требуется.
   Отдельные заблокированные проекты не мешают очистке остальных.
3. Сообщи число удалённых проектов и папок, сохранённых проектов с беседами и существенные препятствия.
   Повторная проверка `cleanup` подтверждает отсутствие удалённых регистраций.

Удалять разрешено только подтверждённые проекты `/upwork-init` строго старше 72 часов, в которых нет ни одной беседы в Antigravity, C1 и C2.
Архивные, дочерние и ещё пустые беседы тоже считаются; учитываются привязка к проекту и рабочий каталог, включая подпапки.
При недоступной/неизвестной истории, неоднозначной регистрации или изменении данных сохраняй проект и указывай причину.
Нельзя считать неизвестное число бесед нулём.
Новые проекты содержат `created_at`; для прежних инструмент использует время создания каталога Windows, иначе верхнюю границу даты запроса в Europe/Istanbul.

Очищаются нативные регистрации Antigravity, общий каталог и нативные регистрации Codex C1/C2, привязки Folders и только те пустые ветки, которые опустели из-за этой очистки.
Codex изменяется через установленный UI-помощник Shared-Projects; прямые записи в его JSON/SQLite запрещены.
Если необходимый профиль Codex закрыт, проект получает `pending` без отложенного удаления; укажи профили, которые нужно открыть, и повтори команду после их открытия.
После частичного сбоя временная `cleanupHold` предотвращает самовосстановление регистрации; следующий запуск продолжает по тому же ID, проверяя беседы заново.
Если за это время появилась беседа, инструмент снимает отметку удаления и восстанавливает отсутствующие регистрации с теми же ID.
В Antigravity незавершённую операцию хранит `.gemini/config/projects/ꘖ/data/cleanup-pending.json`; после подтверждённой очистки её запись удаляется.
Эта временная квитанция хранит регистрационный JSON и нужную ветку Folders для восстановления при отмене; постоянный каталог удалённых проектов не ведётся.
Codex удаляет нативные регистрации первым шагом, а их общие метаданные — после подтверждения Antigravity; при незавершённой фиксации повтори команду.

Все файлы и подпапки `C:/work/upwork/code/proposals/daily` сохраняются целиком, в том числе `.md`, `KB`, `source`, журналы, агентская KB и метаданные.
`proposals/daily/ꘖ/data/projects.json` — постоянный индекс Upwork ID → историческая папка; он нужен для повторных обращений и не является мусором.
Регистрационные квитанции внутри архива — история прежних действий, а не доказательство текущего наличия проекта в UI.
Не удаляй нативные беседы, их вложения/логи, настройки доверия, общие резервные копии и незавершённый staging.
