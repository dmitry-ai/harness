# Первичный анализ Upwork

Результат: проект, полная первоначальная карточка и агентская KB, пять этапов анализа по INIT-3, точный журнал и единый контекст.
Общие правила подключаются нативно из единого источника; в новом проекте перечитай их, если они ещё не загружены.

## 1. Один снимок
Пользователь вызывает `/upwork-init <URL>` в Antigravity 2.0 UI; дальнейшие действия выполняет агент.
Внутренний скрипт: `C:/work/upwork/code/AI/primary/result/.agents/scripts/upwork_project.py` (ниже `<инструмент>`).
Проверь `doctor`; параметры среды и требуемые модели — в `.agents/runtime.json`.
Модель основного A.A — Gemini 4 Argon High. Наличие роли в тексте не подтверждает фактическую модель.
Делегируй по REVIEW-1 через `invoke_subagent`: сложное — `self` с моделью A.A, простое — `af-worker` с tier `flash`.
Передавай точный корень нового проекта и пути общих правил: субагент не получает историю родителя. Сверяй доступные метаданные модели/High; отсутствие проверки укажи явно.

Создай свой каталог `AI/primary/result/ꘖ/data/incoming/<job_id>-<уникальный ID>` и выполни:
```text
python <инструмент> inspect <URL> --output <каталог>/source.json
```
При неоднозначности выбери существующую вкладку через `--tab-id`; не подменяй выбором произвольного аккаунта.
При повторе используй уже сохранённый снимок; не перезаписывай его.
Изучи все существенные вложения; ошибки и границы выгрузки находятся в `coverage`.
`history_complete: false` не разрешает называть выгрузку полной историей аккаунта.
Если недоступная часть истории существенна, получи её доступным авторизованным способом с отдельным доказательством; границы неизвлечённого укажи явно.

## 2. Идентификация и создание
Имя каталога — обоснованный домен без схемы/`www`, иначе короткая тема.
Найденный URL — упоминание; принадлежность сайту клиента требует гипотезы по DOC-2.
Сохрани её отдельно в `site.json`: `id`, `essence`, `for`, `against`, `probability_percent`, `assessment_basis`; каждый довод содержит `argument`, `source`, `quote`.
Если принадлежность не установлена, не передавай гипотезу и используй тематическое имя.
```text
python <инструмент> init <URL> --from-json <каталог>/source.json --domain <имя> --site-hypothesis <каталог>/site.json --date YYYY-MM-DD
```
Дата — дата запроса в Europe/Istanbul; передай её явно, если работа пересекла полночь.
При неизвестном сайте опусти `--site-hypothesis`.
Скрипт создаёт структуру, первоначальный `KB/Project.md`, его полную копию в `ꘖ/KB/Project.md`, неизменяемый снимок и копии вложений с хешами.
Повторный init не заменяет ручные/дополненные файлы.

## 3. Анализ
Выполни пять этапов INIT-3: идентификация → беспокойства → возможные заблуждения → причины у этого клиента → способы решения.
В KB используй F/H/M и устойчивые ID; не превращай слова клиента и предположения в факты.
Причины ссылаются на беспокойства, способы — на причины/задачи.
Каждая H содержит суть, конкретные за/против, экспертную правдоподобность и основание; каждая M — суть, за/против, оценку, критерий и основание.
Все существенные тезисы подтверждай цитатами и ссылками; документация — до проверенного anchor; без Markdown-таблиц и HTML-якорей.
Допустимо не установить заблуждений; отсутствие данных не заполняй выдуманными причинами.

Механические проверки поручай A.F, независимую оценку причин/способов и спорных утверждений — субагенту A.A (`self`).
Используй штатный инструмент текущей беседы, чтобы вызовы, прогресс и результаты были видны в UI; не подменяй их отдельным CLI-сеансом.
Передай область чтения, источники и проверяемый результат; затем проверь вывод и обработай существенные замечания.
Не запускай конкурентных писателей в один файл или одной браузерной сессии.

Сохрани структурированный анализ в `ꘖ/KB/Analysis.json`; схема — `scripts/README-agent-tools.md`, проверка:
```text
python <инструмент> validate-analysis <проект>/ꘖ/KB/Analysis.json
```
При необходимости `--render <новый файл>` формирует Markdown без перезаписи существующего документа.

## 4. Завершение
Обнови профильные модули KB, сохрани первичные доказательства и точный пользовательский запрос/окончательный ответ через `record_step.py`.
Проверь локальные файлы/anchors, внешние источники и их содержательную пригодность; пересобери Context.md.
```text
python <scripts>/validate_links.py <целевые Markdown-файлы> --local-anchors
python <scripts>/validate_anchors.py <целевые Markdown-файлы> --include-code
python <scripts>/generate_context.py --root <проект> --config <проект>/.agents/context.json
```
Удаляй только собственные временные файлы после проверки постоянных копий; снимки, существенные скриншоты и доказательства сохраняй.
